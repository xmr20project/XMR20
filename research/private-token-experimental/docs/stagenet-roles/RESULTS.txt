TESTS — stagenet-roles.test.mjs (node --test; SIMULATED; ports 8951-8953, 30080-30083)

2. A tampered server cannot substitute parameters: a second service with a byte-flipped normal.public-pk (query vector)

     (daemon reports nettype "fakechain")").
   - manifest kind "mainnet": refused at both layers ("Unsupported network "mainnet" (offline-fakechain or stagenet
     only; mainnet refused)").
   - manifest genesis mismatch: refused before any process. A non-daemon URL (the parameter server): refused.
   - positive: fakechain manifest + XMR20_INTEGRATION_RPC_URL (a wrong legacy port variable is ignored): both roles
     start, report the trusted manifest sha256, mainnet-format addresses on the fakechain.
   - startHeight 1000 above the tip: roles start, indexer replays nothing (0 canonical blocks), no error.

RESTART, LOST-REPLY AND RECOVERY CASES — 24 October 2026 (stagenet/recovery-cases.mjs, holder-process.mjs, lossy-proxy.mjs)
Design: each "installation" is a separate OS process (holder-process.mjs = wallet-lib + the extension's encrypted journal module
on a file-backed store) behind a loopback fault-injection proxy that can drop the daemon's REPLY after the daemon answered
(evidence logged) or drop the REQUEST before the daemon saw it. --crash-at kills the process (SIGKILL) right after a named phase
was journaled. A FRESH installation is an empty directory with the same root ("phrase"): it knows the chain, not the journal.
Rule enforced everywhere: COMPLETED only with 10 confirmations on chain; uncertain/conflicting/rejected is never shown as completed.
Fixes made (validation, maturity and confirmation rules untouched; see review/06 §F):
- holder-carrier.js publishWithRecovery/lookup: a transport failure is UNCERTAIN — the daemon is asked (get_transactions) before
  any retry; the SAME blob is re-sent only when the daemon positively does not know the txid; every attempt is journaled first.
- holder-carrier.js quote: key images spent by UNCONFIRMED pool transactions are excluded from native input selection (found when
  a restarted installation re-picked the input its own unconfirmed carrier had spent; the daemon correctly refused the double
  spend; the smoke-run evidence of the defect is kept in runs/recovery-smoke.*).
- holder-process.mjs: explicit journal states and exit codes (0 completed/released, 2 pending, 1 failed/refused/rejected/
  conflicted); a completed record that disappears after a rollback is reinstated and the same carrier re-sent.
