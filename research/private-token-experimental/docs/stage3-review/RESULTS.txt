B. ENGINE-LEVEL RECOVERY CASES — holder-journal-recovery.test.mjs, PASSED 410 s
   (runs/holder-journal-recovery-test.log, runs/holder-journal-recovery-results.json)
================================================================================================
Two "installations" of one holder = two engines from the same root (A original, A2 fresh), Beta
as recipient; real offline daemon; exact balances and fee consequences asserted at every step.
 1  prepared, not proved (quoted) ........ phrase sees nothing; cancel releases; fee 0.
 2a proved, not carried; the fresh install spends the same note first ........ A's saved record
    fails local admission: NO carrier built, fee 0; balances A 91.5 / Beta 7 identical in both
    installs; no inflation.
 2b-i proved AND signed (never broadcast); the other install spends the same note using the SAME
    XMR input (largest-first in the same wallet) ........ when A later broadcasts, the daemon
    refuses the stale carrier as a double spend of the XMR input: fee 0, record never on chain.
 2b-ii same, but the other install used a different XMR input ........ A's stale carrier is a valid
    Monero transaction: it MINES (fee 3,024,000,000 piconero LOST) and the pool rejects its record
    (duplicate nullifier); Beta credited once; A's balance follows the chain (unchanged). Local
    admission already rejected the record before the broadcast - the wallet must consult it; the
    popup now does (section A).
 3  broadcast, reply lost ........ same blob re-sent (2 broadcasts), 1 fee; the fresh install sees
    the record from the chain once mined.
 4  confirmed, then a 12-block rollback (pop_blocks 395 -> 383, pool flushed) ........ both
    installs reset and replay: record gone, spent notes unspent again, recipient's credit gone,
    the carrier's XMR input unspent again; the same signed carrier is accepted again and re-mined
    (same txid); second fee 0; balances exactly as before the rollback afterwards.
 5  two installs spending the same note concurrently (both carriers broadcast before mining) ....
    outcomes [rejected, accepted]: exactly one record admitted; Beta credited once; both wallets
    agree with the chain; BOTH carrier fees paid (loser's fee 3,025,200,000 lost). Unavoidable
    without a shared journal; the loser is shown as rejected, never as a success.
What the phrase cannot do: reconstruct an unpublished proof or signed carrier (fresh randomness,
fresh ring); those exist only in the original journal. Documented in RECOVERY-CASES.txt.
