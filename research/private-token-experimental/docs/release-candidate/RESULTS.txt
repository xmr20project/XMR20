5c. STALLED INTEGRATION RUN (attempt 2, 24 Oct 23:50 local) — DIAGNOSED, PRESERVED, FIXED (no assertion changed)
  Observation: the run passed its first ten suites and then stayed at interop.test.mjs for over an hour; runs/interop-results.json
    had zero transfers, the evidence folder held steps.json=[] and a zero-request audit, the test runner, its child and one
    Playwright Chromium stayed alive without a fakechain, and no integration-report.json was written.
  Cause (confirmed by reproduction, runs/interop-attempt1-stalled/harness-fix-smoke.txt case 3): this candidate had NO
    wallet-extension/extension-private-holder-test build — only the stagenet build had been copied — so Chromium was started with
    a non-existent --load-extension path, no extension service worker appeared and h.launch threw
    "browserContext.waitForEvent: Timeout 30000ms exceeded while waiting for event "serviceworker"" 30 s after launching the
    browser. h.launch created the context and waited BEFORE returning it, so the test's `context` stayed null: its finally closed
    the backend and wrote the empty audit, the test failed, and the still-open browser kept the process alive. The runner buffered
    all child output until exit and had no bound. The hypothesis "launch leaks the context when the service-worker wait throws" is
    CONFIRMED; the trigger was the missing build. Evidence: runs/interop-attempt1-stalled/ (README, process snapshot, the attempt's
    suite log ending in the shell's "exit 143" from the termination, interop-results.json, empty evidence folder).
  Cleanup: exactly four processes were terminated (suite runner 89967, `node --test interop.test.mjs` 4756, its child 4757, its
    Chromium 5608); the stagenet node and everything else were left alone.
  Fixes: (1) wallet-extension/server-patch/extension-auth.mjs (plain source the copy had dropped; the build imports it) restored
    and the local test extension built inside the candidate (identity in RELEASE-CHECKLIST 0; nothing installed changed);
    (2) browser-harness.mjs h.launch refuses a missing build before any browser starts and, if the service worker never appears,
    closes the context itself and throws an error naming the build (smoke: valid build loads in 1.1 s; missing build refused;
    service-worker-less build -> error after 30 s, browser closed, process exits); (3) integration-suite.mjs streams each suite's
    output to runs/suite-logs/, echoes failures and a heartbeat per minute (bounded), bounds every suite and terminates its whole
    process group at the bound, and reports the build identity (wasm, extension bundles, manifest, backend, harness sha256).
  Coverage reconciled: the runner now includes migration/legacy-migration.test.mjs (it was missing from the list), runs
